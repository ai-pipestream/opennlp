## 1. Addons JIRA to file first

Project: OpenNLP, component geoentitylinker (addons). Suggested summary:

geoentitylinker: back the opennlp.tools.geo Gazetteer seam with the Lucene gazetteer index

Description:

OPENNLP-1879 introduces a gazetteer and geocoder seam in opennlp-api (Gazetteer, Geocoder, GazetteerEntry, GeoPoint) with a small bundled public-domain implementation. The geoentitylinker addon already maintains the heavyweight data backend this seam is designed to admit: the Lucene-indexed USGS and GeoNames gazetteers behind GazetteerSearcher.

This ticket proposes implementing the Gazetteer interface over that index once the seam merges. The addon keeps its index format, its Lucene dependency, and its linker unchanged; the new surface is a lookup adapter, so consumers of the seam can swap the bundled table for the full-scale datasets without code changes. A possible second step, separate decision, is exposing the addon's resolution as a Geocoder implementation.

The addon's scoring heuristics (country and province mention proximity, geographic coherence via geohash binning, fuzzy matching) are the reference design for the seam-side disambiguation follow-up to OPENNLP-1879, and they will be credited as such there.

## 3. Rewritten PR #1154 body

Adds the location-intelligence seam and its first implementation.

**Contracts** in opennlp-api (`opennlp.tools.geo`): `GeoPoint`, `GazetteerEntry`, `AttributeValue`, `Gazetteer`, `GeoResolution`, `Geocoder`. Generic in shape: the dataset is an implementation, never the contract. Attributes are provenance-tagged, with a documented external-id key convention (`fips`, `geoid`, `zcta`, `wikidata`, `geonames`, `whosonfirst`) so downstream enrichment joins on stable keys, and ISO 3166-1 alpha-2 is the region join key shared with the emoji annotation layer. No new dependencies.

**Implementation** in a new `opennlp-extensions/opennlp-geo` module:

- `BundledGazetteer` over a project-authored 7,342-row public-domain table derived from Natural Earth Populated Places: fail-loud cursor parser, lazy single load, matching through the shared NFC/case/accent folding chain.
- `PopulationPriorGeocoder`: deterministic population-plus-feature-class ranking, documented heuristic confidence, unresolved mentions omitted.

**Relationship to existing work**, stated upfront:

- The geoentitylinker addon has linked LOCATION spans against USGS/GeoNames data since 2013. This PR neither replaces nor duplicates it: the addon's gazetteer access is coupled to its Lucene index format and has no reusable lookup contract, which is the gap this seam fills. The proposal on the addons side (OPENNLP-XXXX) is for that index to become the large-scale `Gazetteer` implementation behind this seam, and the addon's scoring heuristics are the reference design for the disambiguation follow-up here.
- `Geocoder` sits beside the existing `EntityLinker` contract rather than implementing it, deliberately: `EntityLinker` results are string-typed (`BaseLink` ids plus a score map) and configuration flows through a properties file, while this seam is typed end to end (spans in, `GeoPoint`-carrying entries out) and configured in code. `EntityLinker` is untouched and stays; if consumers want their geocoder results through existing linker plumbing, a small adapter is a follow-up I am willing to write.
- `GeoPoint` is a two-field immutable record, latitude and longitude, so the API does not pull a spatial-geometry dependency for a coordinate pair. If the community prefers standardizing on an existing type, that is a one-record swap and I am open to it.

LICENSE gains the Natural Earth public-domain section; audit tests enforce the data file's documented claims row by row.

**Data derivation:** Natural Earth 1:10m Populated Places via the nvkelso GitHub mirror (upstream commit 789c9904, VERSION 5.2.0-pre), NAMEASCII canonical, wikidata/geonames/whosonfirst ids carried as published, no fabricated fips/geoid/zcta.

Verification: api 328/0 (42 new), opennlp-geo 55/0, 19-module reactor verify green.

Follow-ups (deliberately out of this PR): opennlp-distr wiring plus the binary LICENSE section, disambiguation scoring behind `Geocoder` that ports the geoentitylinker addon's heuristics (country and province mention proximity, geographic coherence, fuzzy matching) with credit, the Overture and GeoNames data tiers, the `EntityLinker` adapter if wanted, and the gRPC mirror after one review round.

https://issues.apache.org/jira/browse/OPENNLP-1879

## 4. Reply bank (paste only when the matching question arrives)

### A. "Why a new Geocoder instead of implementing EntityLinker?"

EntityLinker stays and nothing here touches it. The reason Geocoder is a separate contract is typing: BaseLink carries string ids and a map of named scores, and EntityLinker configuration flows through EntityLinkerProperties files. A geocoding consumer needs coordinates, population, and provenance-tagged attributes as types, not strings to re-parse, and needs construction in code for testability. The two compose rather than compete: an adapter exposing Geocoder results as LinkedSpan/BaseLink is about one class, and I will write it if there are consumers with existing linker plumbing. The geoentitylinker addon keeps implementing EntityLinker exactly as it does today.

### B. "What about disambiguation? Population prior is not enough."

Agreed, and that is why the PR calls its geocoder a population prior and reports heuristic confidence rather than pretending. The disambiguation follow-up is planned as pluggable scorers behind the Geocoder seam, and the design source is the geoentitylinker addon's ensemble, which encodes the right heuristics: country and province mention proximity (a toponym near a mention of its parent country is likely in that country), document-level geographic coherence via geohash binning (a document is usually about one region, outliers score down), fuzzy string matching (Levenshtein and Dice), and place-type priors. Those will be reimplemented against the typed seam, without the Lucene coupling, with the addon credited in javadoc and JIRA as the origin of the approach. The addon's doccat-based context scorer needs a model-distribution story and waits.

### C. "7,342 places is tiny."

It is, deliberately. The bundled table is the zero-setup tier: public domain, so it can ship inside an Apache release, and big enough for country/capital/major-city resolution that most document pipelines need. The scale tiers are follow-ups because their data cannot be bundled: GeoNames is CC-BY (distribution posture tracked in LEGAL-732), so it stays a download-at-setup implementation of the same interface, which is exactly what the geoentitylinker addon's index already is (see OPENNLP-XXXX for retrofitting it onto the seam), and an Overture tier is on the same path. The point of the seam is that consumers write against Gazetteer once and choose the tier by construction.

### D. "GeoPoint duplicates existing geo types."

It is a two-field immutable record, latitude and longitude, with validation. It exists so opennlp-api does not take a spatial-geometry dependency for a coordinate pair; anything needing real geometry converts at the boundary with two accessors. Same simple name as the geoentitylinker addon's index DTO, different package and role; the addon class is coupled to its index row format. If the community prefers an existing type or a different name, it is a one-record swap and I am open to it.

### E. "Why is the dataset project-authored instead of shipping the upstream file?"

The committed derivation script regenerates the table from the published Natural Earth release, and the audit tests verify every documented claim about the data row by row. That makes the provenance checkable by anyone: run the script, diff the output. The alternative, checking in an opaque copy of a third-party file, is what we wanted to avoid after finding mojibake in an earlier cut of exactly this data (fixed by the same script now committed).
